Implementation status: planning decisions vs the PoC

Audit date: 2026-11-10. PoC = iteration 2 on poc/python-flask (developed on poc/state-machine, merged 2026-11-18; webapp/state_machine/, UI webapp/web/ over the JSON API webapp/api.py, spec webapp/SPEC.md). Iteration 1 is frozen on tag poc-iteration-1; its results are the golden suite, so iteration 2 behaves the same. Verified against the code (grep/read) and the test suites (175 app tests + 214 package tests pass). Paths are relative to webapp/state_machine/ unless they start with webapp/.

Status keys: Implemented · Partial · Not implemented (decided, not built) · N/A (planning-only, deferred, superseded, or "no change" decisions). The planning model is much broader than the PoC. "Not implemented" is a normal status.

Summary: ADRs 0001–0061: 16 Implemented, 26 Partial, 14 Not implemented, 5 N/A. CRITIQUE findings (37): 13 implemented, 13 decided but not built, 11 need no code (no change or documentation only).

PoC field names differ from the domain model: dollarsOf = baseDate; openedDate / openingBalance = openedOn / openingValue; annualReturn = returnRate; nonRegistered / rrsp / tfsa = TAXABLE / TAX_DEFERRED / TAX_FREE. The PoC has no warnings channel: every "the result warns" decision is unbuilt.

5. Docs vs code inconsistencies found
