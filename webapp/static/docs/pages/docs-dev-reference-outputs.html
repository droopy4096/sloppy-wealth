Run outputs

state_machine.engine.run_detailed(scenario) (facade state_machine/api.py) validates the scenario (ValueError with a readable message if invalid), compiles and runs it, and returns:

{"rows": [...], "holdings": [...], "ledger": [...], "tax": {...}, "events": [...]}

run(scenario) returns only rows. simulate(scenario) runs without validating and returns the Household (for tests). The result is assembled by results.assemble (state_machine/results.py); events is added by run_detailed.

Amounts are Decimal. The JSON API (POST /api/run) sends them as decimal strings; web/client.py turns the known numeric keys back into Decimal.

rows

One dict per month of the horizon, the state at the end of the month (after the tax step and cash balances), recorded by results.Recorder at Order.CLOSE.

ColumnMeaning
month"YYYY-MM".
cashCash balance. May be negative.
investmentsSum of account balances and pension values.
assetsSum of property and vehicle values.
debtsSum of mortgage balances (positive = owed).
assetsNetWorthinvestments + assets − debts (wealth held outside cash, ADR-0050).
netWorthcash + assetsNetWorth.
limit columnsOnly when the scenario has a limits item: CA rrspRoom, tfsaRoom (room left at month end; None before the room's as-of month); US k401Limit, iraLimit, hsaLimit (left this calendar year; None before limitYear). Household totals over persons. From jurisdiction.limits.remaining.
realNetWorthnetWorth in dollars of the base date (dollarsOf, default horizon start): netWorth / (1 + annualInflation)^((m − base)/12), rounded. Equal to netWorth without inflation.
realAssetsNetWorthassetsNetWorth deflated the same way.

holdings

One entry per holding, in slot order: cash first, then each holding item (account, pension, mortgage, property, vehicle) at the position of its first item. Holdings that never come into existence still have an entry with empty points.

KeyMeaning
id"cash" or the item id.
nameDisplay name.
kindcash, property, vehicle, mortgage, account, pension.
groupcash, property (property and vehicle), debts, investments (account and pension).
pointsOne per month the holding exists, see below.

Point fields:

FieldHoldingsMeaning
monthall"YYYY-MM".
openingallBalance at the start of the month; None in the month it was created.
closingallBalance at the end of the month.
rateallMonthly rate (property, vehicle, account, mortgage: the current one, after renewals); the annual indexing rate for a pension; None for cash.
interestmortgageLOAN_INTEREST of the month.
paidmortgageLOAN_PAYMENT + PREPAYMENT + LOAN_PAYOFF + INTEREST_ADJUSTMENT of the month.
principalPaidmortgagepaid − interest.
closingPenaltymortgage with a termThe penalty if the loan were closed after this month (ADR-0073).

ledger

Every movement, in order. Format and kinds: ledger.md.

tax

{"YYYY-MM": detail}, one detail per month, written by TaxRule (rules/tax.py):

KeyMeaning
taxableTaxable income of the month.
deductionsDeductions of the month.
poolInCarried-forward deductions before the step.
usedDeductions used against taxable income.
poolOutCarried forward to next month.
rateRate applied (None in the household sum when there are several persons).
retiredWhether the person was retired (None in the household sum).
incomeTaxrate × (taxable − used), rounded.
ownRateTaxTax at accounts' own withdrawal rates.
totalincomeTax + ownRateTax (the TAX movement).
personsOnly with several persons: {person id: detail}; the other keys are then household sums.

events

The event log (D-E4): every applied event in order (emitters.EventLog.records).

KeyMeaning
month"YYYY-MM", or None for the INITIAL step (holdings existing at the start).
keyOrder key (order, ordinal, sub) of the emitter (a list in JSON).
emitterEmitter class name, e.g. IncomeEmitter.
eventEvent class name, e.g. Income.
kindlifecycle, flow, valuation or state.
sourceItem id (or None for scenario-level events).
causeIndex of the event that produced it as a follow-up, else None.
ledger(start, end): the ledger lines it produced, ledger[start:end].
detailOne-line description, e.g. "income 5000.00 taxable".
