Jurisdictions

A jurisdiction is a tax country as a plug-in package (ADR-0071). It decides the account types and how each is taxed, its own item types, its contribution limits and their result columns, and wording for the forms. The core engine has no country rules.

  • API: state_machine/jurisdictions/__init__.py.
  • Packages: state_machine/jurisdictions/ca/ (Canada), state_machine/jurisdictions/us/ (United States).
  • A scenario names one with "jurisdiction": "CA"; a scenario without the field is Canadian (DEFAULT = "CA"; upgrade.py inserts it).

Treatment

Frozen dataclass: how money in an account type is taxed.

FlagMeaning
deductibleMoney put in reduces the contributor's taxable income.
returns_taxedThe monthly return is taxable income of the owner (a loss gives no credit).
withdrawal_taxedMoney taken out is taxable income of the owner (or taxed at the account's withdrawalTaxRate).

Predefined: DEFERRED (True, False, True), EXEMPT (False, False, False), TAXABLE (False, True, False). The US package adds HSA (True, False, False).

Hooks

Called by the account events with the rounded amount household.move returned.

HookCalled fromDefault
on_contribute(household, account, amount, source=None)InvestmentAccount.accept_contribution (own share only), Transfer.applyIf deductible and the scenario is not expensesCovered: tax_of(account.contributor).add_deduction(amount).
on_return(household, account, ret)AccountReturn.applyIf returns_taxed: tax_of(account.owner).add_taxable(max(0, ret)).
on_withdraw(household, account, amount)Withdrawal.applyIf withdrawal_taxed: with withdrawalTaxRate, add_own_rate_tax(amount × rate); else add_taxable(amount) for the owner.

Not called for OPENING_TRANSFER / OPENING_BALANCE or the employer match. Override a hook and call super() for the rest (Canada does this for the RESP grant).

ContributionLimits

Interface for limits; the base class allows everything (NO_LIMITS).

MemberMeaning
columns{result column: heading}. Names must end in Room or Limit (the conformance test checks; web/client.py converts such columns to Decimal).
cap(household, account, amount, match=False)The part of amount the account may receive now; uses it up. match=True for an employer match.
note_earned(household, amount, person=None)Earned income of a person this month.
note_withdrawal(household, account, amount)A withdrawal (limits that give room back).
remaining(household){column: amount or None} added to each result row.

capped_note(requested, allowed) gives the event-log note when a movement was capped.

Registration and discovery

  • @jurisdiction("XX") sets cls.code and stores one instance in REGISTRY.
  • discover() imports every sub-package of jurisdictions/ and every module inside it (so @item_type factories in, e.g., ca/room.py register too). compiler.discover() calls it.
  • Look-ups: registered() (all), get(code) (ValueError if unknown), of(scenario), of_or_default(scenario), code_of(scenario), own_item_types() ({type: code}).
  • The household keeps its jurisdiction as household.jurisdiction.
  • Changing a scenario's jurisdiction (POST /api/settings) is refused while items need the old one (ops.switch_problem names them).

CA

Canada, jurisdictions/ca/.

accountTypeLabelTreatmentExtra fields
tfsaTFSA (tax-free)EXEMPT
rrspRRSP (tax-deferred)DEFERREDcontributor (spousal RRSP)
nonRegisterednon-registered (returns taxed)TAXABLE
respRESP (education savings, with the CESG grant)EXEMPTunusedGrantRoom, grantReceived, contributedSoFar
  • Own item type: contributionRoom (ca/room.py).
  • Limits: RoomLimits (ca/room.py), columns rrspRoom, tfsaRoom. Room per (person, account type); a movement uses its account's contributor's room. For an resp account cap applies the RESP lifetime limit instead ($50,000 less contributedSoFar).
  • on_contribute override: after the default, an RESP pays the CESG grant (ca/resp.py pay_grant, a GRANT movement): 20 % of the amount, limited by the grant room ($500 per calendar year from the horizon's first year plus unusedGrantRoom), $1,000 a year and $7,200 lifetime less grantReceived (ADR-0072).
  • validate_item: contributionRoom checks; RESP fields only on resp accounts, not negative.
  • Sample: jurisdictions/ca/sample.json.

United States, jurisdictions/us/.

  • Sample: jurisdictions/us/sample.json.

Conformance test

state_machine/tests/test_conformance.py runs over every registered jurisdiction. A new package must pass it unchanged:

  • declarations: two-letter upper-case code, a name, at least one account type, AccountType keys equal their codes, extra fields appear on the account form, limit columns end in Room or Limit;
  • own item types: each has an @item_type factory, required, form_fields and a legend, belongs to one jurisdiction only; owned_types, add_groups, head_adds list only own types;
  • forms: schema.describe(code) builds, every type is in exactly one add group, the accountType choices are the account types, other jurisdictions' types are absent;
  • sample: jurisdictions/<code>/sample.json exists, uses every account type and own item type, validates, runs, shows a limit column, and is in the jurisdiction's golden set.

Run: cd webapp && .venv/bin/python -m unittest state_machine.tests.test_conformance.

Golden sets

Each jurisdiction has its own golden results (state_machine/tools/update_golden.py): Canada's set is state_machine/tests/golden/ (scenarios.json, golden.json, values.json); another jurisdiction's is state_machine/tests/golden/<code>/ (US: golden/us/). update_golden.py --check compares all sets; --jurisdiction XX picks one, and --add FILE adds a synthetic scenario to it. Steps for a new jurisdiction: state_machine/README.md, "Contributing a jurisdiction".
