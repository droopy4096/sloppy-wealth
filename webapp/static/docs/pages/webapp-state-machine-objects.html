Object inventory of the reference engine (webapp/engine.py)

References to engine.py / "the reference" point to iteration 1 on branch poc/python-flask (tag poc-iteration-1).

Purpose: everything a re-implementation must reproduce to give byte-identical repr(run_detailed(s)) and identical validate() errors. Line numbers (L123) refer to webapp/engine.py at the branch point. Where webapp/SPEC.md disagrees with the code (e.g. "sale at opening value", "taxable income credited net"), the code is the reference.

Conventions used below:

  • D(x) = Decimal(str(x)). All JSON numbers go through Decimal(str(raw)); never Decimal(float). Default context (precision 28, never changed).
  • money(x) = x.quantize(Decimal("0.01"), ROUND_HALF_EVEN) (L80).
  • power(b, e) = (b.ln() * e).exp() (L106). Used for every fractional power. Integer powers use ** (exact Decimal power) — the two must not be swapped.
  • month_index("YYYY-MM-DD") = y*12 + m - 1 (L111); month_label(i) = f"{i//12:04d}-{i%12+1:02d}" (L122).
  • PER = {"month": 1, "quarter": 3, "year": 12} (L1082) is the divisor.
  • Truthiness on raw JSON values decides "given / not given" almost everywhere (item.get(x)): "", missing, 0, 0.0, false are "absent"; the string "0" is present. Ports must test the raw value, not the parsed Decimal.
  • Ledger move(kind, src, dst, amount, source) (L580): amount = money(amount); if 0 → no line, returns Decimal 0.00; else apply -amount to src, +amount to dst, and append {"month", "kind", "from", "to", "amount", "source"} (that key order). _apply (L576): for kind in LIABILITIES=("mortgage",) the delta is negated (money from a loan raises its balance). None = outside the model. Negative amounts are recorded.

Names in the state-machine engine (since E7). This inventory predates the emitter model; the "phases" below are the reference step stages, now the clock.Order numbers (phase × 100, INTERFACES.md §10.2). The planned handler classes became emitters and events: a dated event (§3) → a OneShotEmitter (or ModifierEmitter for improvement, market adjustment, sale, renewal, lump sum) emitting an Event; a recurring process (§4) → a RecurringEmitter; holdings at the start → an InitialEmitter; the runtime RetirementEvent (§3.10) → RetirementEmitter emitting a Retirement state event; the tax step (§4.9) → TaxEmitter / TaxStepEvent; the results recorder (§7) → Recorder. base.Handler/Event/Process/InitialEvent and clock.Phase no longer exist.

2. Aggregates

Common holding keys: id, name (item.name or id), kind, balance (None = not yet existing; points are only emitted when not None), rate (reported in points). GROUPS (L542): cash→cash, property→property, vehicle→property, mortgage→debts, account→investments, pension→investments.

JSON: id, name, purchaseDate, price, annualAppreciation* (-1<r<1), marketValue (opt, ≥0), legacy sale fields saleDate, sellingCostRate, salePenalty (the property itself acts as its sale item, §3.6).

Internal (L744–772):

Lifecycle: PLANNED (balance None) → ACTIVE → SOLD (balance 0, sold True, stays in opened forever after, points continue with closing 0.00).

  • Pre-horizon (at < start, L767–772): balance = money(base * (ONE + rate) ** (start - at)), base = value or amount; integer power; no ledger line; ACTIVE from month 1 (in opened).
  • at >= start: activated by Purchase in ACQUIRE of month at (§3.1). Not in opened that month → no growth in purchase month.

Growth (L1011–1013): if balance truthy (current) and fixedAt != month: APPRECIATION None→id, opening[id] * rate, src=id. Points: opening, closing, rate (monthly rate).

2.2 Vehicle (type: "vehicle") — WP3

JSON: purchaseDate, price, annualDepreciation* (-1<r<1), annualMaintenance*, maintenanceIncrease (opt, -1<r<1). No marketValue (always value None). Can be sold by a sale item whose property = vehicle id (not by legacy saleDate). Internal as property except: rate = power(ONE - D(annualDepreciation), ONE/12) - 1 (negative), upkeep = D(annualMaintenance) (annual, unrounded), upkeepRate = D(maintenanceIncrease or "0"). Lifecycle/pre-horizon/growth identical to property (growth kind is still APPRECIATION, negative amounts). Maintenance (L906–911, holdings order, all holdings): if balance is not None and not sold and not covered: MAINTENANCE cash→None, indexed(upkeep, upkeepRate, m - at, 12), src=id. Includes purchase month; anniversaries from real purchase (also pre-horizon).

2.3 Mortgage (type: "mortgage") — WP4

JSON: principal, annualRate (0≤r<1), amortizationYears* (×12 whole, ≥1), startDate (opt if property given), property (securedBy), firstPaymentDate (opt).

Internal (L732–743):

annuity(balance, r, n) (L519): money(balance / n) if r == 0 else money(balance * r / (1 - (1 + r) ** -n)).

Balance sign: positive = owed. Lifecycle: PLANNED → (LoanAdvance at at) → ACCRUING (at < m < firstPay) → AMORTIZING → PAID_OFF (balance 0.00; never serviced again). Serviced only if in opened and balance > 0 at SERVICE_DEBT time (L899–901), so not in the advance month, and not in a month a sale paid it off.

Per serviced month pay_mortgage(h, m) (L969–1005), in order:

  1. Renewal if (id, m) in renewals (§3.7).
  2. term = h.get("term") or id.
  3. If m < firstPay (ACCRUING): interest = move(LOAN_INTEREST, id→None, amount * rate, term) (on the rounded principal, simple, raises the balance); accrued += interest; return (no payment, left unchanged, extras skipped).
  4. If accrued truthy: INTEREST_ADJUSTMENT (None if covered else cash)→id, accrued, term; accrued = 0.
  5. LOAN_INTEREST id→None, balance * rate, term.
  6. left -= 1; owed = balance; payment = owed if left <= 0 else min(payment, owed); LOAN_PAYMENT (None if covered else cash)→id, payment, term.
  7. Extras for this loan, extras list order (§3.8 lump sums, §4.3 extra payments).

Points: opening, closing, rate (current monthly rate, changes at renewal), plus interest, paid, principalPaid (§7.2).

2.4 InvestmentAccount (type: "account") — WP5

JSON: accountType* ∈ (tfsa,rrsp,nonRegistered), annualReturn* (-1<r<1), openingBalance (opt ≥0), openedDate (opt, blank = horizon start), openingFrom (""/cash/outside), withdrawalTaxRate (opt 0≤r<1, used for rrsp).

Internal (L624–638): accountType; rate = power(ONE + D(annualReturn), ONE/12) - 1; withdrawalTaxRate = D(w) if w else None (raw truthiness: number 0 → None → taxed as income); openingBalance = money(D(openingBalance or "0")); openingFrom = openingFrom or "outside"; with at0 = month_index(openedDate) if openedDate else start: at = at0 if at0 > start else None; balance = openingBalance if at0 <= start else None.

Growth (L1014–1019, every opened account, no balance check): ret = move(RETURN, None→id, opening[id] * rate, id); if nonRegistered: taxable += max(Decimal(0), ret) (ret is the rounded result, 0.00 if dropped). Points: opening, closing, rate (monthly return).

3. Events (discrete, dated)

3.1 Purchase (property / vehicle) — WP3

Trigger: h["at"] == m, ACQUIRE phase (L840–854), loop over list(holdings.values()) (mixed kinds with LoanAdvance and AccountOpening). Effects: balance = Decimal("0.00"); PURCHASE cash→id, amount, id; if value truthy: REVALUATION None→id, value - amount, id. Pre-horizon purchases never fire (at < start).

3.2 LoanAdvance (mortgage) — WP4

Same loop, kind mortgage: balance = 0.00; LOAN_ADVANCE id→cash, amount, id (balance becomes +amount). A mortgage item listed before its property advances first.

3.3 AccountOpening — WP5

Same loop, kind account with at == m (only when opened after start): balance = 0.00; openingFrom == "cash" → OPENING_TRANSFER cash→id, openingBalance, id; else OPENING_BALANCE None→id, openingBalance, id. Zero balance → no line, but account exists.

3.4 Improvement — WP3

JSON: property, improvementDate, cost*, valueAdded (opt). Internal (L680–686): cost = money(D(cost)), at, valueAdded = money(D(valueAdded)) if valueAdded else cost (raw truthiness: number 0 → cost). IMPROVE phase (L856–859), item order, at == m: IMPROVEMENT cash→property, cost, iid; REVALUATION None→property, valueAdded - cost, iid. Properties only (validated).

3.5 MarketAdjustment — WP3

JSON: property, adjustmentDate, exactly one of percent (-1<p<1) / newValue (≥0). Internal (L616–623): percent = D(percent) if percent else None, newValue = money(D(newValue)) if newValue else None. ADJUST phase (L862–870), item order, at == m: percent → change = balance * percent (balance after this month's improvements); else change = newValue - balance, h["fixedAt"] = m (no APPRECIATION this month). MARKET_ADJUSTMENT None→property, change, iid.

3.6 Sale — WP3

Sources: sale item (property = property or vehicle id, saleDate or atRetirement, sellingCostRate, salePenalty, salePrice) or legacy property with saleDate (then sale fields are read from the property; saleId = property id). property_sales(items, retirement) (L58): dict asset id → sale item, in item order; atRetirement sale copied with saleDate = retirement (when retirement set); dateless sale items skipped; second sale of same id → ValueError "is sold more than once". Attached to the asset at prepare (L760–765): saleAt, sellingCost = D(sellingCostRate or "0"), salePenalty = D(salePenalty or "0") (unrounded), salePrice = money(D(salePrice)) if sale and salePrice else None (raw 0 → None → sells at value), saleId = sale.id or asset iid. SELL phase (L871–887), loop list(holdings.values()), saleAt == m:

  1. if salePrice is not None: SALE_PRICE_DIFFERENCE None→id, salePrice - balance, saleId.
  2. price = balance; sold = True; SALE id→cash, price, saleId.
  3. SELLING_COST cash→None, price * sellingCost, saleId.
  4. for loan in holdings.values() (holdings order) with securedBy == id and balance truthy: LOAN_PAYOFF cash→loan, loan.balance, saleId (includes any accrued interest).
  5. PENALTY cash→None, salePenalty, saleId.

Effect on same month: paid-off loan skipped in SERVICE_DEBT; asset gets no maintenance (sold) and no growth (balance 0). No capital-gains tax (C-M8).

3.7 Renewal — WP4

JSON: mortgage, startDate, annualRate*, amortizationYears (opt), penalty (opt). Internal (L687–692): key (mortgage, month_index(startDate)) → (monthly_rate(annualRate), int(D(amort) * 12) if amort else None, D(penalty or "0"), iid). Fires inside pay_mortgage step 1 (only if the loan is serviced that month; else silently lost, incl. penalty): rate = r; term = rid; left = reset or left; payment = annuity(balance, rate, left) (current balance, before this month's interest; in ACCRUING months this includes accrued interest); PENALTY cash→None, penalty, rid.

3.8 LumpSum — WP4

JSON: mortgage*, paymentDate or atRetirement, amount or payOff: true, paidFrom (cash default / outside), penalty. Internal (L701–710): first = last = retirement if atRetirement else month_index(paymentDate); amount = None if payOff else money(D(amount)); recurring False; fromCash = (paidFrom or "cash") == "cash"; penalty = D(penalty or "0"). Fires in pay_mortgage step 7 (after the scheduled payment, in extras order): src = "cash" if fromCash else None (independent of covered); amt = balance if amount is None else min(amount, balance); PREPAYMENT src→loan, amt, iid; then PENALTY cash→None, penalty, iid (charged even if PREPAYMENT was 0). Skipped entirely in ACCRUING months or when the loan is not serviced.

3.9 Transfer — WP5

JSON: account, amount (>0), transferDate or atRetirement. Internal (L609–615): at = retirement if atRetirement else month_index(transferDate), amount = money(D(amount)). TRANSFER phase (L890–895), item order, after sales: TRANSFER cash→account, amount, iid (from cash even when covered); if account is rrsp and not covered: deductions += amount.

4. Recurring processes / flows

active(f, m) = f["first"] <= m <= f["last"] (L791). indexed(base, rate, k, divisor=1) (L534) = money(base * (ONE + rate) ** (k // 12) / divisor) (integer power, anniversary step). Indexing rate resolution (all flows): inflation → self.inflation; custom → D(indexRate); else Decimal(0).

4.1 Income / Expense — WP7

JSON: amount+per / legacy monthlyAmount; startDate (blank allowed with startsAtRetirement); endDate; startsAtRetirement/endsAtRetirement; indexing, indexRate; amountIn (start default / base); taxable (income only, default false). Internal (L711–731): first = retirement if startsAtRetirement and retirement is not None else month_index(startDate); last = month_index(endDate) if endDate else end, then min(last, retirement - 1) if endsAtRetirement and retirement set; base = amount, and if amountIn == "base" and inflation (truthy): base = amount * power(ONE + inflation, Decimal(first - self.base) / 12) (unrounded); divisor = PER[per]; taxable = kind == "income" and item.get("taxable", False).

  • EXPENSE phase (L902–905), flows order, active and not covered: EXPENSE cash→None, indexed(base, rate, m - first, divisor), iid.

Covered mode: no line at all.

4.3 ExtraPayment — WP4

JSON: mortgage, startDate, endDate, endsAtRetirement, monthlyAmount* (>0). Internal (L693–700): first, last (endDate or end; endsAtRetirement cap), amount = money(D(monthlyAmount)), recurring True. 4.4 Contribution — WP5 (account) / WP6 (pension target)

JSON: account* (account or pension id), startDate*, endDate, endsAtRetirement, amount/per, indexing, employerMatch (0..1). Internal (L656–671): first = startDate, last, rate, base, divisor, match = D(employerMatch or "0"). CONTRIBUTE phase (L915–936), item order; skip unless active and target balance is not None: amount = indexed(base, rate, m - first, divisor).

  • Account: CONTRIBUTION (None if covered else cash)→acct, amount, iid; if rrsp and not covered: deductions += amount; then EMPLOYER_MATCH None→acct, amount * match, iid (always outside; not income, not deduction).

4.5 Withdrawal — WP5

JSON: account, method ∈ (amount,percent,annuity; even = unindexed annuity), startDate (blank = retirement), endDate, endsAtRetirement, amount/per+indexing (amount), annualRate (percent, 0<r<1), indexing (amount, annuity). Internal (L656–679): first = startDate or retirement, last, rate, method; amount → base, divisor; percent → annualRate = D(annualRate); mutable monthly. WITHDRAW phase (L938–967), item order; skip if not active:

  1. percent and (m - first) % 12 == 0: bal = opening.get(acct.id, acct.balance) or Decimal(0); monthly = money(bal * annualRate / 12) (runs even if balance is 0/None).
  2. if not acct.balance: continue (None or 0).
  3. amount: indexed(base, rate, m - first, divisor); percent: f.get("monthly", Decimal(0)); annuity (ADR-0039 am. 2026-11-11): final = min(last, end); in final request the whole balance; else if monthly unset or (m - first) % 12 == 0: monthly = money(balance / annuity_factor(acct.rate, rate, final - m + 1)) (growing annuity, g = indexing rate; closed form in flows/withdrawal.py), use it.
  4. amt = move(WITHDRAWAL, acct→cash, min(amount, balance), iid).
  5. rrsp: withdrawalTaxRate is not None → extra_tax += amt * withdrawalTaxRate (unrounded); else taxable += amt. tfsa/nonRegistered: untaxed.

Covered mode: unchanged (still into cash, still taxed).

6. Exact intra-month ordering (step, L775–789)

  1. OPEN: month = m; taxable = deductions = extra_tax = Decimal(0); opened (holdings order, non-cash, balance not None); opening = {id: balance}. (run separately snapshots every holding incl. cash for points, L1055.)
  2. INCOME: flows in item order, kind income → INCOME.
  3. PENSION_PAY: holdings order, pensions → PENSION_PAYMENT.
  4. ACQUIRE: list(holdings.values()) order, at == m: per holding PURCHASE[, REVALUATION] | LOAN_ADVANCE | OPENING_TRANSFER/OPENING_BALANCE.

9. Parity hazards found (surprising or fragile)

  1. Raw-truthiness defaults: numeric 0 (not "0") for marketValue, salePrice, valueAdded (→ cost), withdrawalTaxRate (→ taxed as income), retirementTaxRate (→ no switch), amortizationYears on renewal (→ keep remaining term).
  2. Validation raises KeyError (not ValueError) for a sale/improvement/marketAdjustment without property, an account without accountType, a withdrawal without method.
  3. Holdings order = item order across kinds; duplicate ids keep the first slot; items without id become item{n} and cannot be referenced.
  4. ACCRUING mortgage: interest is simple on the rounded principal but raises the balance; left only counts from firstPay; a renewal in that window annuitises principal + accrued; lump sums / extras (and their penalty) in that window are dropped.
  5. Renewal or lump sum on a loan already at 0 (e.g. prepaid off) is silently lost with its penalty; a lump-sum PENALTY is charged even when its PREPAYMENT rounds to 0.
  6. Payment is annuitised on the unrounded principal; the advance uses the rounded one.
  7. Points: interest/paid/principalPaid default Decimal('0') (exponent 0) while ledger sums carry 0.00; pension rate is the annual indexing rate, others monthly.
  8. Sold assets keep balance 0.00 (not None): they stay in opened, keep emitting points, and growth is suppressed only by the zero balance.
  9. Covered mode drops EXPENSE/MAINTENANCE/pension contribution lines entirely but keeps loan-payment and contribution lines with from None; TAX is still taken from cash.
  10. extra_tax and amountIn: base amounts stay unrounded until their final use.
  11. Percent withdrawal re-bases on opening.get(id, balance) (current balance in the account's opening month); the annuity is set from the current balance at the first non-zero month and re-set on each anniversary of first.
  12. Pension indexing counts years from the base date; flows count from their first.
  13. pension_value uses power for the inflation factor but an integer ** for the real ratio; preserve both expressions exactly.
