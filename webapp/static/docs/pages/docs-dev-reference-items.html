Scenario items

A scenario is one JSON object: some settings and a list of items. Each item has a type. This page lists every item type the engine registers (compiler.registered_types()), with its fields, links, run behaviour and code. webapp/SPEC.md is the longer spec; where it and the code differ, this page follows the code.

Conventions used in the tables:

FormatMeaning
decimalA decimal string, e.g. "1500" or "1500.50". JSON numbers are also read (through str), but an optional field holding the number 0 counts as "not given".
fractionA rate as a decimal string fraction: "0.035" is 3.5 %. The builder form shows percentages; web/pages.py converts them (ADR-0045).
date"YYYY-MM-DD". Only year and month are used (ADR-0007).
boolJSON true / false (not strings).
idThe id of another item.
choiceOne of the listed strings.

"Required" means validation (state_machine/validation.py) refuses the item without it. Many dates are required but may come from a trigger instead of the item itself. Order names (INCOME, SERVICE_DEBT, ...) are the steps of the month: see modules.md#month-order. Ledger kinds link to ledger.md.

Common item fields

FieldRequiredFormatMeaning, default
typeyeschoiceThe item type (sections below). Unknown types are refused; a type of another jurisdiction is refused with its name.
idno (yes for person)stringUnique in the scenario. Other items refer to it. Without one the compiler uses item<index>; /api/load and /api/items/add assign 8 hex characters.
namenostringDisplay name. /api/items/add fills in the type name.
enablednoboolDefault true. false leaves the item out of the run, together with every item that refers to it through property, mortgage, account, flow, event, target, parent, owner, contributor or retirementOf, and every item a start trigger on it would start (enabled.py, ADR-0064).
ownernoid of a personOnly on income, account, pension, retirement, and the jurisdiction's own contributionRoom / contributionLimit. Blank: the first person. Contributions and withdrawals take their account's owner.
retirementOfnoid of a personWhose retirement an item follows when its start is blank (pension, withdrawal) or in older at-retirement forms. Default: the owner, else the first person.

Older forms are converted on input by state_machine/upgrade.py (monthlyAmount on flows, withdrawal method even, startsAtRetirement / endsAtRetirement / atRetirement, an expense's attachedTo, a vehicle's annualMaintenance, a property's saleDate, a sale's sellingCostRate). The engine reads only the current forms below.

Each item type is compiled by one factory registered with @item_type("<type>"). The factory returns emitters; emitters produce events each month; events record ledger movements. See modules.md.

withdrawal

Regular draws from an account into cash.

FieldRequiredFormatMeaning, default
accountyesid of an account
methodyeschoice amount, percent, annuitySee below.
startDatenodateBlank: the owner's retirement month (a retirement item is then required). percent and annuity may not start before the account opens.
endDatenodateBlank: horizon end.

Methods (flows/withdrawal.py):

  • amount: the indexed amount.
  • percent: on the start and each anniversary, annualRate / 12 × the balance at the start of that month; paid monthly for a year (ADR-0049). An empty account at an anniversary pays 0 that year.
  • annuity: spends the account down by min(endDate, horizon end); set from the balance in the first month with a balance and re-set each anniversary, at the account's own return; with indexing the payment grows yearly by the indexing rate; the final month takes the whole balance (ADR-0039 amendment).
  • Run: WITHDRAW step: WITHDRAWAL account → cash, capped at the balance; nothing while the balance is 0. Then on_withdraw (taxable income of the owner, or tax at withdrawalTaxRate) and note_withdrawal (CA TFSA room).
  • Code: state_machine/flows/withdrawal.py (compile_withdrawal, WithdrawalEmitter, AmountStrategy, PercentStrategy, AnnuityStrategy, Withdrawal).
